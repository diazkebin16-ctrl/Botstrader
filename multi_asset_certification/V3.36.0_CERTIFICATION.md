# BotsTrader V3.36.0 — Multi-Asset Foundation Certification

## Scope
This release generalizes the V3.35.3 EUR_USD baseline into an instrument-aware foundation and incorporates GBP_USD as a defined secondary instrument without automatically granting it PAPER execution authority.

## Baseline provenance
- Local source package: `BotsTrader_V3.35.2_GITHUB_READY.zip`.
- Phase-0 local change: `VERSION_TAG 3.35.2 -> 3.35.3` only.
- GitHub reference: `6d7f2bc29ce1f96b560e96e95413bcfc69e66dfe`.
- Every root Python file in the local package after the version bump was Git-blob-SHA compared with the GitHub reference and matched exactly.
- GitHub contains additional documentation/configuration/evidence files not present in the clean ZIP; those are not overwritten by this release workflow unless explicitly changed.

## Baseline test observation
After the Phase-0 version-only bump, `compileall` passed. Pytest collected 226 existing tests: 223 passed and 3 failed solely because those tests still hard-coded `3.35.2`. GitHub `6d7f2bc` contains the same stale assertions, so this was a known version-contract drift rather than a trading/security regression.

## Architecture implemented
- Added `instrument_registry.py` for symbol normalization, display precision, pip location, trade-unit precision, minimum trade size, margin metadata, price formatting and unit normalization.
- Conservative fallbacks exist for EUR_USD, GBP_USD and future USD_JPY compatibility; OANDA metadata replaces fallbacks when available.
- Execution-enabled instruments and shadow instruments are distinct. Defining an instrument does not activate it.
- GBP_USD is disabled by default. It may be explicitly enabled for OFFLINE/SHADOW observation later without PAPER order authority.
- Scanner processing remains sequential in one worker and failures are isolated per instrument.
- Market-data results, signal identity, learning, discovered patterns, strategy health, adaptive-learning strategy namespace, ML artifacts/model runs, forward observations, trade management and recovery retain instrument attribution.
- Legacy/global research authority is restricted to the primary EUR_USD population; GBP_USD cannot inherit an EUR_USD learned research veto.

## Execution / sizing / risk
- Orders always carry the requested instrument explicitly.
- Price and unit formatting use instrument metadata.
- Secondary execution requires execution-enabled mode and broker-verified metadata; GBP_USD remains disabled by default.
- Instrument-aware sizing may reduce requested/legacy units but never increase them.
- Existing global hard risk ceilings, leverage policy and correlated-position controls were not increased.
- No new correlation veto was invented for GBP_USD.
- Broker-confirmed fill price remains the trade-management entry reference.
- Existing `body=` safety for mutating OANDA requests remains covered by regression tests.

## Persistence / recovery
- Existing signal and observation tables already carried instrument attribution.
- Added non-destructive indexes for instrument-scoped queries.
- Added `instrument_discovered_patterns` keyed by `(instrument, pattern_key)`.
- Added backward-compatible `model_runs.instrument` with default EUR_USD for historical rows.
- Strategy-health keeps historical EUR_USD keys unchanged while secondary instruments use namespaced keys.
- Recovery idempotency and trade restoration preserve symbol identity. Scenario tests restore EUR_USD and GBP_USD simultaneously and verify no cross-contamination after a simulated restart.

## Runtime Integrity
- Release version is `3.36.0`; V3.35.3 is not reused after critical-code changes.
- `instrument_registry.py` is included in SecurityManager critical file hashes.
- `instrument_registry.py` is also included in the production release fingerprint.
- No runtime manifest was edited, deleted, or manually marked verified.

## Operational policies preserved
- No new entries 07:00–10:00 America/New_York.
- No new entries 15:00–19:00 America/New_York.
- Existing managed positions continue management during entry blackouts.
- Weekday daily/rollover cutoff 16:50–19:00 remains in effect.
- No RR, spread, barrier, break-even, anomaly, ensemble, governance, leverage, or hard-risk threshold was relaxed to make GBP_USD trade.
